# bRainDead · 레인 데드

Godot 4.7.2로 만든 2D 물리 조작 게임 프로토타입입니다. 바람으로 버려진 우산을 움직여, 멋대로 집에 가는 민트를 비로부터 보호합니다.

## 실행

`project.godot`을 Godot 4.7.2에서 열고 **F5**를 누르세요. 메인 씬은 `scenes/main.tscn`입니다. 광고 재생용 Godot WRY 웹뷰 확장은 `addons/godot_wry`에 포함되어 있으며 .NET은 필요하지 않습니다. YouTube 광고 영상은 인터넷 연결과 Windows의 Microsoft Edge WebView2 Runtime을 사용합니다.

| 키 | 동작 |
| --- | --- |
| A / ← | 누르는 동안 왼쪽 바람 |
| D / → | 누르는 동안 오른쪽 바람 |
| 양쪽 동시 입력 / 입력 없음 | 바람 없음 |
| Enter / Space | 타이틀에서 시작, 스테이지 대기 화면에서 출발 |
| R | 플레이·실패·일시정지 중 즉시 재시작 |
| Esc | 일시정지 / 계속 / 이전 화면 |
| M | 음향 켜기·끄기 |

## 구현한 규칙

- 우산은 `RigidBody2D`입니다. 바람은 수평 힘, 위쪽 힘, 회전력을 동시에 가합니다. 이동 감쇠는 0.18로, 입력을 끊고 1초가 지나도 가로 속도의 약 83%가 남습니다. 중력 배율은 2.4, 상승 힘은 688.8로 바람을 최대로 주면 중력을 제외한 순상승 가속이 304.8px/s²입니다. 가로 속도는 330px/s, 상승은 210px/s, 낙하는 850px/s까지 각각 제한합니다. 반대 바람과 장애물 충돌로 회전·이동을 되돌릴 수 있습니다.
- **플레이어 우산은 뒤집혀도 비를 막습니다.** 자동 자세 복구는 없습니다.
- 비는 수직으로 내리며 생성 위치·높이·간격이 조금씩 무작위로 달라집니다. 생성 간격은 기준의 80~120%, 낙하 속도는 88~112% 범위이고 빗줄기 길이와 밝기도 달라집니다. 각 빗방울의 이전 위치에서 다음 위치까지 Godot 물리 공간에 충돌 검사를 하여 빠른 빗방울의 관통을 방지합니다. 처음 닿은 곳에서 소멸합니다.
- 플레이어 우산, 바닥, 간판은 비를 막습니다. **행인과 행인 우산은 비 판정에서 제외되므로 민트를 보호하지 않습니다.** 행인 우산은 화면에만 그리며 물리 바디·충돌 모양·히트박스가 없습니다. 플레이어 우산이 그대로 통과합니다.
- 민트에게 닿는 빗방울 수와 관계없이 젖음은 **초당 1초 증가**, 보호받으면 **초당 1초 감소**합니다. 0~2초로 제한되며 2초에 도달하면 실패합니다. 실제 빗방울 사이의 빈 프레임은 0.055초의 접촉 유지 시간으로 이어줍니다.
- 민트는 젖음에 비례하여 파란색으로 변합니다. 길 오른쪽의 집에 도착하면 클리어합니다.
- 2·3단계에서는 달리기 시작 위치에서 약 1초 동안 멈춰, 상체를 숙이고 손을 바닥에 짚는 육상 출발 준비 자세를 취한 뒤 달립니다. 준비 시간은 스테이지의 `run_prep_duration`으로 조정합니다.
- 민트 행동과 행인 경로는 고정되어 있습니다. 재시작하면 우산의 위치·속도·회전, 민트, 행인을 초기화하고 비는 새로운 무작위 패턴으로 시작합니다. 검증에서는 `PhysicalRain.reset(seed)`로 같은 비를 재현할 수 있습니다.
- 4개 스테이지는 순서대로 해금됩니다. 클리어와 시도 횟수는 Godot의 `user://progress.cfg`에 저장합니다.
- 클리어 후 ‘다음으로’를 누르면 게임 창 안에서 [지정된 YouTube 영상](https://www.youtube.com/watch?v=liCoGtVaw_M)을 자동 재생합니다. 오른쪽 위에 **10 → 9 → … → 1초 뒤 스킵 가능**을 표시하고, 10초가 되는 순간 **건너뛰기** 버튼을 활성화합니다. 건너뛰기를 누르면 영상·오디오를 종료하고 스테이지 선택으로 돌아갑니다. 카운트다운이 끝나도 자동으로 화면을 넘기지 않습니다.
- 광고 중에는 빗소리와 스테이지를 멈춥니다. 영상 로드 오류나 네트워크 장애가 나도 10초 뒤 건너뛰기로 계속 진행할 수 있습니다.

## 스테이지와 조정 위치

| 파일 | 내용 |
| --- | --- |
| `stages/01_walk.tres` | 일정 속도로 걷기 |
| `stages/02_run.tres` | 고정 위치에서 1초 동안 출발 준비 자세를 취한 뒤 달리기 |
| `stages/03_trip.tres` | 출발 준비 뒤 달리다가 고정 위치에서 넘어지고, 2.6초 후 일어나 걷기 |
| `stages/04_crowd.tres` | 고정 경로의 행인 84명이 길 전체에 붐비는 번화가 |

각 `.tres`를 Godot Inspector에서 열면 길이, 이동 속도, 달리기·넘어짐 위치, 출발 준비·넘어짐 정지 시간, 군중 수, 우산 시작 위치, 간판 위치를 바꿀 수 있습니다. 좌표는 민트의 발 위치를 기준으로 하며 바닥은 Y=600입니다. 화면은 1280×720 기준이며 민트를 따라 횡으로 이동합니다.

우산의 수평 힘·상승 힘·회전력·가로·상승·낙하 속도 제한은 `scenes/umbrella.tscn`의 Inspector에서 조정할 수 있습니다. 중력·감속은 `scripts/umbrella.gd`에 있습니다. 현재 값은 강한 관성과 빠른 상하 이동을 위한 조정값이며 최종 난이도 수치는 아닙니다.

## 구조

- `scripts/main.gd`: 타이틀, 선택, 대기, 플레이, 일시정지, 실패, 클리어, 광고 및 저장
- `scripts/video_ad.gd`: YouTube 웹뷰, 10초 스킵 잠금, 영상 정리 및 화면 복귀
- `ads/youtube_ad.html`: YouTube 플레이어와 오른쪽 위 광고 카운트다운·건너뛰기 UI
- `scripts/stage.gd`: 지형·캐릭터·우산·비 구성 및 스테이지 진행
- `scripts/mint.gd`: 위치 기반 행동, 넘어짐, 젖음 및 캐릭터 그리기
- `scripts/umbrella.gd`: 바람 물리와 우산 그리기
- `scripts/rain.gd`: 위치·간격·속도가 무작위로 달라지는 물리 충돌 비
- `scripts/pedestrian.gd`: 고정 경로의 행인 및 비를 막지 않는 우산
- `scripts/city.gd`: 직접 그린 벡터 도시 배경
- `scripts/sound.gd`: 외부 파일 없이 합성한 빗소리와 효과음

한국어는 시스템의 맑은 고딕 / Noto Sans CJK KR / Apple SD Gothic Neo를 사용합니다. 그래픽은 Compatibility 렌더러를 사용합니다.

## 검증

Godot 실행 파일을 PATH에 등록했다면 다음 명령으로 실제 엔진 기반 검사를 실행할 수 있습니다.

```powershell
godot --headless --path . --editor --import --quit
godot --headless --path . --script res://tests/gameplay_test.gd -- --no-save
godot --headless --path . --script res://tests/physics_playtest.gd --fixed-fps 60 -- --no-save
```

Windows에서는 아래 도우미도 사용할 수 있습니다. 검사 프로필은 임시 폴더로 분리하여 실제 플레이 기록을 건드리지 않습니다.

```powershell
powershell -ExecutionPolicy Bypass -File tools/run_checks.ps1 -GodotPath 'C:\path\to\Godot_console.exe'
```

검사 범위: 플레이어·행인 우산 비 충돌, 군중 밀도·충돌 객체 부재·플레이어 우산의 군중 우산 통과, 뒤집힌 우산의 보호, 젖음 증가·회복·사망, 비 밀도 독립성, 여러 무작위 비 패턴의 젖음·시드 재현, 출발 준비 자세·정지 시간·달리기·넘어짐 및 재시작 재현, 고정 행인 경로, 실제 엔진에서의 관성·낙하·상승 속도, 방향키 입력, 재시작, 일시정지, 해금, 저장, 광고 10초 카운트다운·조기 스킵 차단·명시적 스킵 복귀·재진입·재생 오류 시 복귀. Headless 검사에서는 웹뷰를 만들지 않으므로 실제 YouTube 재생은 창 모드에서 확인합니다.

`physics_playtest.gd`는 플레이어와 같은 왼쪽·오른쪽·무입력만 사용해 4개 스테이지를 끝까지 진행하는 자동 조작 검사입니다. 우산이나 민트의 위치를 강제로 옮기지 않습니다. 양쪽 바람을 번갈아 사용해 고도를 조절하고, 달리기가 있는 2·3스테이지에서는 간판보다 높은 경로를 택합니다. 비는 스테이지마다 다른 시드로 재현하며 자동 조작은 테스트에서만 동작합니다. 검사 명령 끝에 `--playtest-stage=3` 또는 `--rain-seed=123`을 추가하면 특정 스테이지나 다른 비 패턴을 검증할 수 있습니다.

저장을 생략하고 특정 스테이지를 미리 보려면 다음처럼 실행합니다. 잠금 해제 기록은 바뀌지 않습니다.

```powershell
godot --path . -- --no-save --stage=4
```

광고만 미리 보려면 `godot --path . -- --no-save --ad`로 실행하세요. 광고는 Windows x64에서 검증하는 데스크톱 기능입니다. 포함된 웹뷰는 macOS와 Linux용 런타임도 제공하며 Linux는 WebKitGTK가 필요합니다. Android·iOS·웹 내보내기는 현재 광고 재생 대상이 아닙니다. 데스크톱 내보내기 프리셋을 만들 때 Resources의 비리소스 파일 내보내기 필터에 `ads/*.html`을 포함해야 합니다.

실제 영상 재생과 HTML 버튼까지 자동 검사하려면 창 모드·인터넷 연결 상태에서 `godot --path . --script res://tests/ad_playback_test.gd -- --no-save`를 실행하세요. 이 검사는 요청된 영상의 자동 재생, 10~1초 표시, 조기 클릭 차단, 0초 버튼 활성화, 스킵 후 복귀와 웹뷰 해제를 확인합니다.

## 현재 범위

임시 벡터 그래픽과 합성 음향을 사용하는 플레이 가능한 프로토타입입니다. YouTube 삽입 재생을 광고 화면에 사용하며 실제 광고 SDK와 최종 아트·애니메이션은 포함하지 않습니다.
